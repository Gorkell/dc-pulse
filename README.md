# Інтелектуальна IoT-система моніторингу та прогнозування технічного стану дата-центру

DC Pulse — учебное веб-приложение с украинским интерфейсом, сервером Flask, SQL-базой, серверной симуляцией, прогнозом температуры и обработкой инцидентов. Учебных документов в исходной папке не было: модель взята из задания. Отчёт курсовой не создаётся.

## Запуск на Windows

Нужен Python 3.11+ и интернет для первой установки пакетов. Node, Docker, PostgreSQL и сборка интерфейса для локального запуска не требуются. `start.cmd` создаёт локальное `.venv` и устанавливает зависимости при первом запуске.

Из PowerShell в папке проекта:

```powershell
.\start.cmd
```

Открыть [http://127.0.0.1:8000](http://127.0.0.1:8000). Для остановки — Ctrl+C в окне сервера. Первый запуск создаёт `data.sqlite3`, выполняет миграции и добавляет 8 объектов, 18 датчиков и 1098 измерений за 30 минут. Симулятор первоначально на паузе. Перезапуск сохраняет данные, сценарий и состояние паузы/запуска.

Эквивалентные команды вручную:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe app.py
```

Активация виртуального окружения не требуется. Если порт занят, задайте `$env:PORT='8001'` перед запуском. Не используйте `flask run --reload`: основной способ запуска — `app.py` через Waitress.

## Вход

| Логин | Роль | Права |
|---|---|---|
| operator | Оператор | Мониторинг, прогнозы, подтверждение, назначение, закрытие инцидентов; управление демонстрацией |
| engineer | Інженер | Оборудование, телеметрия; только назначенные ему инциденты, начало работы и результат обслуживания |
| admin | Адміністратор | Оборудование, датчики, пороги, пользователи, анализ, демонстрация и защищённый сброс |
| manager | Керівник | Мониторинг, история, прогнозы, сводка и CSV без изменения эксплуатационных данных |

Первоначальный общий **учебный пароль: `Demo-IoT-2026!`**. Это публичная демо-константа, не производственный секрет. При первом заполнении можно установить другой пароль через `DEMO_PASSWORD`. После заполнения смена переменной не меняет существующие хеши: используйте администратора. Пароли хешируются Werkzeug scrypt; исходные пароли не хранятся. Администратор не подменяет оператора в процессе обслуживания. Тестовые имена вымышлены.

## Возможности

Обновление 21.10.2026: миграция `002_targets_and_forecast_epochs.sql` автоматически применяется через `start.cmd` и сохраняет существующую историю. Переустановка и сброс базы не нужны. На экране «Демонстрація» оператор/администратор выбирает температурный датчик стойки и датчик заряда ДБЖ; выбор сохраняется по ID и используется после переименования. Главный график использует выбранную температурную цель. При отсутствии/архивации цели интерфейс объясняет проблему, затронутый сценарий останавливается; выберите активный датчик или восстановите устройство. После подтверждённого сброса цели заново привязываются к новым ID.

Для архивного датчика или оборудования текущий прогноз недоступен. После повторного включения нужны новые измерения и анализ: минимум 6 точек, не менее половины окна анализа, без чрезмерных пропусков. При стандартном окне 30 минут это минимум 15 учебных минут (при ×30 — около 30 реальных секунд непрерывной симуляции). Прежние измерения и результаты расчётов сохраняются. Обе границы правила показаны на всех графиках: красная верхняя и охристая нижняя; для заряда штатная нижняя граница — 30%.

- Огляд, оборудование и карточки с графиками; поиск и фильтр типа.
- История датчика с периодом, временными границами и CSV; до 10 000 строк на выгрузку, до 100 строк в таблице. Большие периоды разбивайте на интервалы.
- Прогноз температуры: регрессия, окно, горизонт, объяснение, расчёт времени достижения верхнего порога.
- Инциденты с фильтрами, назначением, результатами работ, историей автора/времени/комментария.
- Настройки пользователей, датчиков, порогов и анализа. Вместо удаления — архивирование с сохранением истории. Метрика и оборудование существующего датчика неизменны.
- Сводка и CSV инцидентов по фильтру; внутрисистемные уведомления с отметкой прочтения.
- Шесть сценариев симуляции, запуск/пауза, ×1/×5/×15/×30 и отдельный подтверждаемый сброс администратором.

При потере связи измерения не добавляются, последнее значение помечается устаревшим. Таблицы показывают учебное время измерения и реальное время приёма отдельно. Пауза замораживает учебное время, поэтому не вызывает потерю связи. Простой выключенного сервера тоже не проматывается. В интерфейсе это учебная демонстрация, не мониторинг физических устройств.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check static/app.js
node tests/frontend.cjs
```

Тесты создают временные SQLite-базы: права, CSRF, валидация, дубли, конкуренция, прогноз, пороги, потеря связи, назначение, переходы, восстановление, повторная проблема после закрытия, сохранность при повторном запуске, архивирование, CRUD пользователей, экспорт и защищённый сброс.

Набор содержит 23 Python-теста: миграция со старой схемы, чистый запуск, переименование/смена/отсутствие целей, архивирование и повторное включение с накоплением новой истории, устаревание прогноза, восстановление ID после сброса и защита тестовой базы. Node требуется только для проверки JavaScript, не для запуска приложения. Проверка `tests/frontend.cjs` выполняет реальные функции графика и обзора для четырёх метрик и отсутствующей/архивной цели без браузера.

Для PostgreSQL используйте **отдельную пустую тестовую БД**:

```powershell
$env:TEST_DATABASE_URL='postgresql://test:password@localhost:5432/iot_test'
$env:ALLOW_TEST_DATABASE_RESET='1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:TEST_DATABASE_URL
Remove-Item Env:ALLOW_TEST_DATABASE_RESET
```

**Тесты PostgreSQL удаляют и создают схему public перед каждым тестом. Никогда не указывайте рабочую базу.** Защитная проверка разрешает только `localhost`/`127.0.0.1`/`::1`, пользователя `test`, базу `iot_test`, без параметров переадресации соединения и с явным `ALLOW_TEST_DATABASE_RESET=1`. Внешние базы, включая Neon, запрещены. `DATABASE_URL` рабочего приложения не используется для выбора тестовой базы. GitHub Actions создаёт отдельный одноразовый PostgreSQL 16 service container; секреты будущего хостинга в workflow не используются. [Статус GitHub Actions](https://github.com/Gorkell/dc-pulse/actions); файл CI сам по себе не доказывает прохождение PostgreSQL-проверок. Текущие результаты и ограничения — в [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Конфигурация и размещение

Скопируйте `.env.example` в `.env` только при необходимости настройки. Не добавляйте `.env`, БД и `.venv` в Git. Переменные процесса имеют приоритет. Известные переменные: `DATABASE_URL`, `HOST`, `PORT`, `SIMULATOR_ENABLED`, `COOKIE_SECURE`, `DEMO_PASSWORD`.

Целевая архитектура — PostgreSQL; SQLite — упрощённый локальный вариант. Для пустой PostgreSQL-базы достаточно установить `DATABASE_URL=postgresql://...` и запустить тот же сервер. Миграции и первичное заполнение выполняются автоматически. PostgreSQL-драйвер включён в зависимости. Это переключение на другую базу, **не перенос существующей SQLite-истории**: перенос накопленных данных потребует отдельного ETL и сверки количества записей/FK.

Репозиторий исходников: [Gorkell/dc-pulse](https://github.com/Gorkell/dc-pulse). Приложение на хостинге пока не опубликовано. Оно должно запускаться командой `python app.py` на Python-хостинге с постоянно работающим процессом и отдельной PostgreSQL, например на виртуальном сервере или подходящей PaaS. GitHub Pages не запускает этот сервер. До размещения: проверить PostgreSQL CI, задать непубличный `DEMO_PASSWORD` до первого заполнения, включить `COOKIE_SECURE=1`, настроить HTTPS на reverse proxy, `HOST=0.0.0.0`, `PORT` хостинга, `SIMULATOR_ENABLED=1`, резервное копирование БД и управление доступом. HTTPS завершается внешним сервером; TLS внутри приложения не реализован. Не запускайте симулятор как serverless-функцию. Фоновый поток входит в один серверный процесс, SQL lease предотвращает одновременное владение несколькими процессами, но для учебного размещения рекомендуется один экземпляр.

Нет внешних CDN, браузерных сборок и сетевых библиотек графиков. [Waitress поддерживает Windows](https://flask.palletsprojects.com/en/stable/deploying/waitress/); [psycopg использует параметризованные запросы](https://www.psycopg.org/psycopg3/docs/basic/usage.html).
