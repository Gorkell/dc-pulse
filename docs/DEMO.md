# Сценарий показа (около 5 минут)

1. Запустить `start.cmd`. Войти `operator` / `Demo-IoT-2026!`. Показать 8 объектов, историю и график температуры R-01. На «Прогнозування» объяснить линию тренда и ограничение метода.
2. На «Демонстрація» выбрать ×15, «Поступове нагрівання», нажать «Запустити». За несколько десятков секунд появляется прогнозный риск; на горизонте 15 учебных минут линия может пересечь 32 °C.
3. Выбрать «Перегрів стійки». Через несколько тактов появляется отдельный фактический пороговый инцидент. Выбрать паузу после появления. В «Інциденти» открыть пороговый инцидент, подтвердить, назначить Андрія Бондаря.
4. Выйти, войти `engineer`. Открыть назначенный инцидент, начать работу, записать результат и отправить на проверку. Сообщение инженера не восстанавливает показатели.
5. Снова войти `operator`. Попытка закрытия при перегреве будет отклонена. Выбрать «Відновлення» и ×30, запустить. Подождать нормализацию и минимум 120 учебных секунд; смотреть график и статус. Если анализ вернул инцидент в работу, инженер должен повторно отправить его на проверку после восстановления. Затем оператор подтверждает закрытие.
6. Выбрать «Втрата зв’язку» при ×30: после более 180 учебных секунд (примерно 8 реальных секунд) появится проблема свежести. Показать неизменное последнее значение с пометкой «Немає зв’язку». Выбрать «Відновлення».
7. При необходимости показать сценарий питания UPS-01 (×30: около 20–25 реальных секунд до снижения заряда ниже 30%).
8. Выгрузить CSV с выбранным датчиком/периодом, затем инциденты с фильтром состояния. Войти `manager` и показать сводку без эксплуатационных действий. Войти `admin`, показать пороги, пользователей и настройки анализа.

Для повтора с нуля: администратор → «Демонстрація» → «Скинути демонстраційні дані…» → ввести `СКИНУТИ ДЕМО`. Это отдельная необратимая учебная операция, не происходит при загрузке страницы. Начальные пользователи сохраняются.
